# Glyph security scan, 2026-10-12

Scope: dependency advisories (pnpm, cargo), the Tauri command surface and grant registry, the React rendering pipeline and plugin sandbox, `glyph serve`, `glyph mcp`, cloud sync, the preview handlers, CI workflows, and the release supply chain. Findings were traced in code; anything not reproduced in code is listed as unverified.

## Dependency scans

- `pnpm audit`: no advisories (756 packages).
- `cargo audit`: no vulnerabilities. Warnings: `libssh2-sys` 0.3.2 is yanked (fixed in PR 1), `glib` 0.18.5 unsoundness (transitive through Tauri's GTK stack, no fix reachable), six unmaintained `unic-*` and `proc-macro-error` crates (transitive, informational).

## Already covered by open PRs

- Windows network-path lookups in `workspace_resolve`, `vault_forget`, the file-tree commands and the opener: PRs 926 and 927.

## Needs a GitHub setting, not code

- **No tag ruleset.** `release.yml` runs on any `v*` tag with every publish secret, and only `main` has a ruleset. Add a ruleset for `refs/tags/v*` restricting creation to the release deploy key and admins; consider a `release` environment with required reviewers for the publish secrets.
- **`TAP_GITHUB_TOKEN` is a classic `repo` PAT** handed to third-party actions and embedded in clone URLs. Replace with fine-grained tokens scoped per satellite repo.
- **Release signing GPG key has no passphrase** and lives in a repo secret. Set a passphrase, use a subkey with expiry, and publish the fingerprint in the install docs.

## Deferred (documented, not fixed here)

- Release build job runs the whole dependency tree with `contents: write` (asset replacement risk). Fix: split build and upload, emit `SHA256SUMS` from the build and verify in each publish job, add build provenance attestation.
- Dockerfile `ADD` of the release .deb and snapcraft's `curl` of the latest .deb carry no checksum.
- `${{ github.ref_name }}` and version outputs interpolated into `run:` in `release.yml` (tag pushers are already trusted; convert to `env:` when touching the file).
- `validate_remote_url` accepts `ssh://user:pass@host` and uppercase `HTTPS://` through the scp branch (confusing accept, not a bypass).
- Telemetry path redaction misses POSIX roots outside the anchored list and Sentry console-breadcrumb arguments (opt-in telemetry only).
- Sandboxed plugins whose on-disk manifest grew permissions load at startup without re-consent (needs out-of-band file change).
- Canvas link nodes open any opener-scoped scheme without the external-link confirmation.
- Preview page rewrites only `<img>`, not `video`/`audio`/`source`/SVG `image` (CSP and the WebKit rule list still block the fetch).
- Watcher map keyed by path spelling (a renderer can exhaust inotify instances with distinct granted files regardless, so dedupe adds little).
- MCP elicitation disguise check misses format characters (U+200B etc.).
- Full-trust plugin consent lives in renderer-writable `plugins.json`; with Rust-side package verification a compromised renderer can only grant full trust to a reviewed package. Accepted alongside the persisted-session grant staging risk.

## How the gates ran

All Rust tests ran under `setpriv --bounding-set=-dac_override,-dac_read_search` because this container runs as root, where the permission-bit tests (`prune_export_dir_*`, `a_file_that_cannot_be_written_says_so`) would otherwise pass vacuously or fail; with the capabilities dropped they behave as on a CI runner.
